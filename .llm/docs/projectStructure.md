## Component Overview

### Rust Workspace (`src/rust/`)

The Rust workspace is organized as a multi-crate project with the following members:

| Crate | Purpose | Language Bindings |
|-------|---------|-------------------|
| **fcb_core** | Core library with read/write/indexing capabilities | Pure Rust |
| **cli** | Command-line interface (`fcb` command) | - |
| **wasm** | WebAssembly bindings via wasm-bindgen | JavaScript/TypeScript |
| **fcb_api** | REST API server using axum | HTTP API |

Neither Python nor C++ is a Rust workspace member: `src/py/` and `src/cpp/` are
from-scratch, standalone readers with no compiled/Rust dependency (see below).

### Language Bindings / Ports

FlatCityBuf provides native readers for multiple languages, all validated against
the Rust implementation (`src/rust/fcb_core`), which is the authoritative oracle:

1. **Python** (`src/py/`) → Published to PyPI as `flatcitybuf`, a pure-Python
   `py3-none-any` wheel (no Rust toolchain required to build or install; the
   PyO3 extension formerly at `src/rust/fcb_py` was retired in favor of this)
2. **C++** (`src/cpp/`) → Standalone C++ library with CMake build, ported from
   Rust from scratch (no FFI, no Rust dependency at build or run time)
3. **JavaScript/TypeScript** (`src/ts/`) → Published to npm as
   `@cityjson/flatcitybuf`. Today this package wraps the Rust core compiled to
   WASM (`src/rust/wasm`); a from-scratch, native TypeScript reader mirroring
   the C++/Python ports is **in progress**, not yet shipped.

### Build Artifacts (Not Tracked)

- `src/rust/target/` - Rust build artifacts (in `.gitignore`)
- `src/cpp/build*/` - C++ build artifacts (in `.gitignore`)
- `conformance/*.fcb` is the one exception to "binaries aren't tracked": these
  are committed deliberately so the C++/Python/TS suites can run without
  regenerating the corpus via a Rust toolchain.

## Key Patterns

### Workspace Dependency Management

All dependencies are managed at the workspace level in `src/rust/Cargo.toml`. Individual crates use workspace dependencies:

```toml
[dependencies]
fcb_core = { workspace = true }
```

### Code Organization

Each crate follows standard Rust conventions:
- `src/lib.rs` - Library entry point
- `src/main.rs` - Binary entry point
- Feature flags in `Cargo.toml` for conditional compilation

### Cross-Language Bridge

Only WASM uses an FFI/codegen bridge to the Rust core. Python and C++ are
from-scratch reimplementations with no FFI at all, each validated against the
Rust reader as the oracle:
- **Python**: no FFI -- `src/py/` is a standalone, pure-Python reader that
  parses the FlatCityBuf format directly (flatbuffers runtime only; numpy is
  the only optional extra)
- **C++**: no FFI -- `src/cpp/` is a standalone, from-scratch C++17 reader
  that parses the FlatCityBuf format directly (flatbuffers + nlohmann/json,
  libcurl optional for HTTP); it does **not** use a cxx bridge or any other
  Rust interop
- **WASM/TypeScript (current npm package)**: wasm-bindgen compiles
  `src/rust/wasm` (which wraps `fcb_core`) to WebAssembly for browser/Node use
- **TypeScript (in progress)**: a native, from-scratch TS reader mirroring the
  C++/Python approach -- no WASM, no FFI -- is under active development and
  will eventually sit alongside (or replace, for pure-JS consumers) the WASM
  package
